# Security & Execution Limits

KodiScript provides built-in mechanisms to protect your application from infinite loops, overly complex scripts, and long-running execution. This is essential when executing untrusted code or allowing user-defined scripts.

## Instruction Counter (Max Operations)

You can limit the number of operations (instructions) a script executes. This is a deterministic way to prevent infinite loops.

### Usage

import { Tabs } from 'nextra/components'

<Tabs items={['Go', 'Kotlin', 'Dart', 'TypeScript', 'PHP']}>
<Tabs.Tab>
```go
result := kodi.New(script).
    WithMaxOperations(10000).
    Execute()
```
</Tabs.Tab>
<Tabs.Tab>
```kotlin
val result = KodiScript.builder(script)
    .withMaxOperations(10000)
    .execute()
```
</Tabs.Tab>
<Tabs.Tab>
```dart
final result = KodiScript.builder(script)
    .withMaxOperations(10000)
    .execute();
```
</Tabs.Tab>
<Tabs.Tab>
```typescript

    .withMaxOperations(10000)
    .execute();
```
</Tabs.Tab>
<Tabs.Tab>
```php

    ->withMaxOperations(10000)
    ->execute();
```
</Tabs.Tab>
</Tabs>

If the limit is exceeded, execution stops immediately and an error is returned (e.g., `MaxOperationsExceeded`).

## Time-based Timeout

You can also set a maximum duration for script execution. This is useful for ensuring latency SLAs.

### Usage

<Tabs items={['Go', 'Kotlin', 'Dart', 'TypeScript', 'PHP']}>
<Tabs.Tab>
```go
result := kodi.New(script).
    WithTimeout(5 * time.Second).
    Execute()
```
</Tabs.Tab>
<Tabs.Tab>
```kotlin

    .withTimeout(5000)
    .execute()
```
</Tabs.Tab>
<Tabs.Tab>
```dart
final result = KodiScript.builder(script)
    .withTimeout(Duration(seconds: 5))
    .execute();
```
</Tabs.Tab>
<Tabs.Tab>
```typescript
// milliseconds
const result = KodiScript.builder(script)
    .withTimeout(5000)
    .execute();
```
</Tabs.Tab>
<Tabs.Tab>
```php

    ->withTimeout(5000)
    ->execute();
```
</Tabs.Tab>
</Tabs>

If the timeout is exceeded, execution stops and a `TimeoutError` (or equivalent) is returned.

## Recursion Guard <span style={{fontSize: '13px', fontWeight: 'normal', opacity: 0.6}}>Go · Kotlin · TypeScript</span>

Deeply (or infinitely) recursive scripts are stopped before they can exhaust the host's native stack. Call depth is capped at **1000 frames**; exceeding it raises a runtime error (`maximum call depth exceeded`) that you can catch or inspect, instead of crashing the host process.

```javascript
fn loop() {
    return loop()   // unbounded recursion
}
loop()   // -> runtime error: maximum call depth exceeded
```

## Safe Arithmetic <span style={{fontSize: '13px', fontWeight: 'normal', opacity: 0.6}}>Go · Kotlin · TypeScript</span>

To keep behaviour deterministic and identical across these engines, invalid arithmetic raises a runtime error rather than producing `Infinity` or `NaN`:

```javascript
10 / 0    // -> runtime error: division by zero
10 % 0    // -> runtime error: modulo by zero
```

Combine this with [`try`/`catch`](/language-guide/control-flow#try--catch) to recover gracefully.

## Typed Error Kinds <span style={{fontSize: '13px', fontWeight: 'normal', opacity: 0.6}}>Go · Kotlin · TypeScript</span>

Every result exposes an **error kind** so you can react programmatically instead of matching on message strings. The categories are:

| Kind | Meaning |
|------|---------|
| `none` | Execution succeeded |
| `parse` | The script failed to lex/parse |
| `runtime` | A runtime error occurred (bad operation, undefined variable, recursion guard, …) |
| `timeout` | The execution timeout was exceeded |
| `max_operations` | The operation limit was exceeded |

<Tabs items={['Go', 'Kotlin', 'TypeScript']}>
<Tabs.Tab>
```go
result := kodi.New(script).WithMaxOperations(1000).Execute()
if result.Kind == kodi.ErrorKindMaxOperations {
    // handle the limit being hit
}
```
</Tabs.Tab>
<Tabs.Tab>
```kotlin
val result = KodiScript.builder(script).withMaxOperations(1000).execute()
if (result.errorKind == ErrorKind.MAX_OPERATIONS) {
    // handle the limit being hit
}
```
</Tabs.Tab>
<Tabs.Tab>
```typescript
const result = KodiScript.builder(script).withMaxOperations(1000).execute();
if (result.errorKind === 'max_operations') {
    // handle the limit being hit
}
```
</Tabs.Tab>
</Tabs>

## Best Practices

*   **Always set limits** when running untrusted code.
*   **Combine both**: Use `maxOps` for deterministic protection against logic errors (loops) and `timeout` as a failsafe for heavy computation.
*   **Branch on the error kind**: Check `result.errorKind` / `result.Kind` rather than parsing error message text — it's stable across versions and engines.
*   **Sandbox by default**: Scripts can only touch the variables and functions you explicitly inject. See [Extensibility](/language-guide/extensibility) for scoping guidance.
